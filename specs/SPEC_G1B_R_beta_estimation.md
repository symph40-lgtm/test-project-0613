# SPEC — G1B-R: FairGap 측정 파이프라인 실측 검증 (v0.2)

- 문서 버전: v0.2 (G1B v0.3 정합판 — 단순 베타 추정에서 **갭 측정 체계 전체의 오프라인 검증**으로 확장)
- 상태: 구현 대기 (Claude Code 작업용)
- 상위 문서: SPEC_G1B_gap_translation.md v0.3 (§3 채널 분해, §4 σ_night, §12 작업 범위)
- 목적: G1B v0.3의 갭 측정식이 **과거 데이터에서 실제로 갭을 얼마나 정확히 측정하는지**를
  워크포워드로 검증하고, 60일 log-only에 투입할 **초기 파라미터 팩**(β·σ·가중치)을 산출한다.

## 3. 파이프라인 명세 (검증 대상 그 자체)

### 3.1 직교화 순서 (고정 — 순서 변경 금지)

```
1. fx_orth   = resid( Δfx ~ Δy2 )                     [사슬: 금리→환율]
2. soxx_ex   = resid( r_SOXX ~ r_SPX )                [채널: 지수→고유]
3. tsm_ex    = resid( r_TSM ~ r_SOXX )                [고유 내: 섹터→개별]
4. peer_orth = resid( r_peer ~ r_SOXX )               [〃]
```
각 직교화 회귀도 롤링 120일 — 전 표본 일괄 직교화는 룩어헤드이므로 금지.

### 3.2 채널 회귀 (모델 사다리)

```
지수 사다리: I0 = b1·r_SPX → I1 = +금리(b2,b3) → I2 = +fx_orth → I3 = +세션질(b5~b7)
고유 사다리: S0 = c1·soxx_ex → S1 = +peer_orth → S2 = +tsm_ex
결합:       FairGap_hat = β_mkt·G_idx_hat + G_idio_hat
```
- 라벨: 지수 사다리는 KOSPI200 갭, 고유 사다리는 **종목갭 − β_mkt·지수갭** (채널별 자기 라벨로 추정).
- 추정: OLS + Newey-West, 롤링 {60/120/250} 민감도, 주 1회 재추정 시뮬레이션.
- 채택 기준: 상위 단계가 하위 단계의 OOS 오차를 개선할 때만 채택 (v0.1 승계).

### 3.3 σ_base 추정 (v0.3 §4의 전제 — 최우선 산출물)

```
1. 레짐 분류 히스토리 재구성: 이벤트 밤(CPI·PPI·FOMC·고용 발표일 캘린더 + MU·NVDA 실적일),
   대변동 밤(|r_SPX| ≥ 3%), 나머지 평상 밤
2. 워크포워드 잔차를 레짐별로 분리 → 조건부 표준편차 = σ_base(레짐)
3. 커버리지 검정: 각 밤 σ_night = σ_base(레짐)로 실측 잔차의 1σ/2σ 커버율 산출
   (k_event 배율은 implied move 히스토리 조달 곤란 → 60일 로그 이관, 오프라인은 σ_base만)
4. 감도: 레짐별 표본수 확인 — 이벤트 밤 표본 < 40이면 σ_base(이벤트) 신뢰구간 병기
```

### 3.4 가중치 역산

```
w_reg(레짐)·u·v: 워크포워드 각 밤의 {회귀부 예측, 관측부 예측}을 저장해두고,
                 OOS translation_error를 최소화하는 볼록결합 가중을 레짐별로 격자 탐색 (0.1 단위)
γ1~γ3:          R2 재현 가능 표본(아시아 시세 확보분)에서 동일 방식
과최적화 방어:   가중 탐색은 검증기간 전반부에서만 수행, 후반부는 그 가중으로 동결 평가 (2단 분할)
```

### 3.5 워크포워드 총검증 (갭 측정가의 최종 성적표)

```
for each KRX 영업일 d in 검증기간(최근 1.5년):
    직전 금요일까지 데이터로 β·직교화·σ_base 확정 (이후 접근 금지)
    07:15 재현: available_by_0715 변수만으로 FairGap_R1_hat ± σ 산출 (AdjEx 적용)
    기록: translation_error, 잔차의 σ 단위 환산, 레짐, 채널별 오차 분해(지수/고유)
```
- 채널별 오차 분해를 매일 저장 — G1B §9 건강 감시의 히스토리 시뮬레이션(경보가 과거에
  몇 번, 언제 발동했을지)까지 재현해 경보 임계(90분위)의 적정성을 사전 점검한다.

## 4. 구현 구조

```
g1br/
├── config.yaml              # 티커·기간·윈도·레짐 캘린더 소스
├── src/
│   ├── fetch.py             # 수집 + parquet 캐시 + 가용성 등급 태깅
│   ├── align.py             # 시간 정렬 + available_by_0715 플래그 (테스트 필수)
│   ├── ortho.py             # §3.1 롤링 직교화
│   ├── channels.py          # §3.2 이단 회귀 사다리
│   ├── sigma.py             # §3.3 σ_base + 커버리지
│   ├── weights.py           # §3.4 가중 역산 (2단 분할)
│   ├── walkforward.py       # §3.5 총검증 + 건강 경보 시뮬레이션
│   └── report.py            # O1~O8 + param_pack_v1.json
└── tests/test_align.py, test_ortho.py
```
개발 순서: align(+테스트) → fetch → 지수 I0 단독 관통 → 고유 S0 → σ → 가중 → 사다리 확장.
전 과정 결정적(deterministic). 파라미터 탐색 횟수를 로그에 자동 기록 (다중검정 감사).

## 6. 판정 비대칭 (승계 원칙)

> **[개정 고지]** 본 작업의 param_pack_v1.json은 SPEC_G1_OPT_loop.md 챔피언–챌린저 체계의
> **초대 챔피언(pack_v1.0)** 이 되며, 이후 분기 1회 본 워크포워드를 최신 데이터로 재실행해
> 현행 챔피언과 대조한다 (상시 재검증 조항).

양성 결과는 입장권(할인 수용), 음성 결과는 기각 확정. 좋은 숫자가 나와도 60일 log-only를
건너뛰지 않으며, param_pack은 "검증된 초기값"이 아니라 "가장 정직한 출발값"으로 취급한다.

## 7. 실패 시 강등 사다리

1. 가중 재역산 → 2. 세션질·tsm 등 후순위 변수 제거(구조 단순화) → 3. 고유 채널을 soxx_ex
단독으로 축소 → 4. 회귀부 전체를 크기 참고용 강등, 관측부 중심 운영안을 O8에 기술.
각 강등 단계와 사유를 O8에 기록 — 무엇이 실패했는지가 다음 버전의 설계 입력이다.

## 8. 미해결 사항

1. B등급 데이터(야간선물·TAIFEX 히스토리) 조달 결과에 따른 범위 확정 — **구현 첫 주에 판정**.
2. 레짐 캘린더 재구성 소스 (과거 CPI/FOMC/실적 발표일 데이터베이스).
3. 검증기간 1.5년의 레짐 편중 여부 (특정 국면 과대표집 시 3년으로 확장).
4. param_pack의 삼전·하닉 분리 vs 공통 파라미터 항목 구분.
